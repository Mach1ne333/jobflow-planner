# JobFlow Planner · 求职规划助手

参考 [OfferFlow](https://offerflow.com.cn/applications) 的岗位记录思路，额外提供面试、笔试、投递截止日与跟进任务的日程规划。独立开发，不复制其代码或页面。

## 运行

需要 Node.js 20.19+ 或 22.12+，以及 npm。进入项目目录运行：

```bash
npm install
npm run dev
```

浏览器访问终端输出的本地地址（通常为 http://127.0.0.1:5173）。构建检查：`npm run build`。

**Windows 一键启动：**双击桌面的 `JobFlow.cmd`。脚本会切换到项目目录，若服务尚未启动则打开一个终端运行 Vite，待页面就绪后自动用默认浏览器访问；若服务已启动则直接打开页面。使用期间不要关闭新开的服务终端，关闭后本地页面将停止服务。启动逻辑在 `scripts/Start-JobFlow.ps1`，桌面脚本的备份在 `scripts/JobFlow.cmd`。仅在端口 5173 已由 JobFlow 使用时复用它；若被其他程序占用则提示错误，不会打开错误的网页。

## 已实现

- 岗位增删改查、状态筛选与搜索、列表/看板视图。列表中当前状态下方显示该状态日期；岗位详情保留可编辑、可补录的状态时间线，投递日期单独存储。首次标为“已投递”时用投递日期；以后改变状态时默认建议当天并允许改日期。旧数据的已投递日期可从投递日期确定，其他历史阶段日期如未记录则显示“日期待补”，不作推断。
- 单独维护的日程：面试、笔试、截止日期、跟进、其他；可关联岗位，支持全天事项与完成标记。
- 简历管理：版本名称/备注，上传或更换本地 PDF/DOC/DOCX 文件（单份不超过 10 MB），下载、删除、查看关联岗位数；岗位编辑时可选择已有版本。
- 面试记录：同一岗位保存多轮面试，记录日期、面试官、地点/形式、结果、流程、多条问题与回答、特殊提问、提醒及复盘；可关联已有面试日程。只有岗位已进入面试阶段、日程已发生且尚无记录时才提示补写；同一岗位重复日程只提示一次。删除岗位时记录保留并解除关联。
- 周/月日历、今日待办及逾期事项、工作台统计。
- IndexedDB 浏览器本地存储；JSON 备份导出、确认后合并导入（相同 ID 跳过，不覆盖已有记录；新版备份包含简历附件和面试记录）。

无需账号或服务器。数据**只保存在当前浏览器的当前站点**；清理浏览器站点数据、使用隐私模式或更换电脑/浏览器会导致不可访问，请定期使用右上角数据管理菜单导出 JSON 备份。浏览器存储空间有限；重要简历也请在电脑上保留原文件。旧版 v1/v2 备份仍可导入；新版 v3 备份包含简历附件及面试记录，可能较大，妥善保管。导入会合并新增记录，不覆盖同 ID 的现有记录；操作前仍建议先备份。删除岗位时，关联日程会保留，但会解除关联。删除简历时已关联岗位仍保留版本名称，但附件不再可下载。

### 在另一台 PC 恢复数据

1. 在原 PC 打开 JobFlow，点击右上角「数据管理」→「导出 JSON 备份」，保存下载的 `jobflow-backup-日期.json`。这份备份包含岗位及状态时间线、日程、面试问答/复盘和已上传的简历附件（旧备份可能不含新字段）。
2. 用私密方式将备份文件复制到新 PC，**不要提交到公开 GitHub 仓库**。JSON 未加密，含完整私人信息与简历文件内容；建议存放在加密磁盘或受控私人云盘。
3. 在新 PC 克隆代码、运行 `npm install` 和 `npm run dev`（尽量使用 `http://127.0.0.1:5173/`），在网页右上角选择「导入 JSON 备份」。确认后会合并导入，已有相同 ID 不覆盖。核对岗位、面试和简历数量，并抽查几份简历能否下载。导入完毕仍请保留原备份。

浏览器存储按完整地址区分：`localhost` 与 `127.0.0.1`、不同端口或不同浏览器是不同数据空间。桌面启动脚本目前指向 `D:\Project\jobflow-planner`；新 PC 如果克隆到其他路径，请修改 `scripts/JobFlow.cmd` 内的脚本路径，或直接运行 `npm run dev`。

暂不提供系统级后台通知、跨设备同步、自动抓取职位或 AI 功能；请不要把日历中的事项理解为操作系统提醒。

## 技术

React + TypeScript + Vite；FullCalendar 日历；IndexedDB（`idb`）；样式为原生 CSS。

测试：`npm test`（状态历史与面试提示规则）。

主要文件：`src/App.tsx`（界面和交互）、`src/features/resumes/ResumePage.tsx`（简历管理）、`src/features/interviews/InterviewPage.tsx`（面试记录）、`src/lib/storage.ts`（本地数据及备份）、`src/styles.css`（布局和样式）。

## 公开 GitHub 仓库的隐私边界

`.gitignore` 排除了 `data/` 中的个人 OfferFlow HTML/转换 JSON、`node_modules/`、`dist/`、本地备份目录、PDF/DOC/DOCX、环境变量等。求职数据通常不在项目文件里，而在浏览器 IndexedDB；不会随着代码 `git push` 自动上传。`data/.gitkeep` 只占位。**不要使用 `git add -f` 强制添加私人文件**；发布前务必运行 `git status` 和 `git diff --cached --name-only` 检查待提交清单。若文件已被 Git 跟踪，后来写入 `.gitignore` 不能从历史提交中抹掉它，需另行处理历史记录。

## OfferFlow HTML 迁移

如已在 OfferFlow 的岗位投递、面试记录页面分别保存 HTML，可用 `scripts/import_offerflow_html.py` 转为本应用支持的 JSON（需要 Python 与 `beautifulsoup4`）。脚本只读取本地 HTML，不访问网络；源 HTML 与生成的 JSON 均放在被 `.gitignore` 忽略的 `data/` 中。导入前请备份当前数据；右上角设置菜单 → 导入 JSON 备份，选择生成的文件。已折叠、未出现在 HTML 中的面试复盘/JD，以及真实简历附件不能从列表快照恢复；仅导入可见的简历版本名称。此前从 OfferFlow 导入的面试日期属于日程项，会在“面试记录”页面提示补写复盘，不会虚构不存在的问答内容。
